# ChemAssist 开发日志 2026-05-23

## Ketcher 分子结构绘图（P0）

### 背景

用户只能通过文本输入化学物质名称，无法像 ChemDraw/Reaxys 那样手绘分子结构。

### 实现

- 安装 `streamlit-ketcher` 组件（封装 EPAM 开源的 Ketcher 编辑器）
- 在聊天输入框上方添加可折叠的 "🎨 分子结构绘制" 面板
- 用户绘制分子 → 点击 Apply → SMILES 存入 session_state
- 发送消息时自动拼接：`SMILES: xxx\n\n用户问题: xxx`
- 新增 CSS 样式美化绘图面板

### 关键代码

```python
# app.py
from streamlit_ketcher import st_ketcher

with st.expander("🎨 分子结构绘制", expanded=False):
    ketcher_smiles = st_ketcher(value=st.session_state.get("ketcher_smiles", ""),
                                height=400, key="ketcher_editor")
    if ketcher_smiles:
        st.session_state["ketcher_smiles"] = ketcher_smiles
```

## StructureAnnotationTool——分子结构标注（P1）

### 背景

RDKit 能力远不止计算分子量。有机化学学生最需要的功能：识别分子中的官能团、手性中心、E/Z 异构、核心骨架。

### 实现

新增 `StructureAnnotationTool`（`tools/chem_calc.py`），5 个维度：

| 维度 | RDKit API | 示例输出 |
|------|-----------|---------|
| 手性中心 | `FindMolChiralCenters()` | `[{"atom_index": 1, "stereo": "S", "symbol": "C"}]` |
| E/Z 异构 | `bond.GetStereo()` | `[{"type": "E (trans/反式)"}]` |
| 官能团 (22 种) | SMARTS 匹配 | `[{"name": "羧酸", "count": 1}, {"name": "酯基", "count": 1}]` |
| Murcko 骨架 | `MurckoScaffold.GetScaffoldForMol()` | `"c1ccccc1"` |
| 反应活性位点 | SMARTS 匹配 | 亲电位点（羰基碳）+ 亲核位点（NH₂/OH） |

### 踩坑

- **SMARTS 逗号陷阱**：`[NX3H0,H1,H2]` 被解析为 "NX3H0 或 H1 或 H2"（H1 匹配了氧上的 H），而非 "N 带 H0 或 H1 或 H2"。修复为 `[NX3]`。
- **酮 SMARTS 过松**：`[CX3](=O)[#6][#6]` 匹配了羧基碳（羰基→苯环碳→苯环碳）。修复为 `[#6][CX3](=O)[#6]`。

### 测试

`tests/test_chem_calc.py` 新增 11 项（描述符 2 + 标注 6 + Tool 3）

## 记忆系统升级：缓存 → 个人知识库

### 背景

旧版记忆系统是一个无形缓存——用户只知道侧边栏有个数字 N，完全看不到存了什么。

### 改进

**A. 前端可视化**
- 侧边栏新增 "📚 个人知识库" 区域
- 表格展示所有条目（名称、SMILES、缓存时间、命中次数）
- 可搜索筛选、单条删除

**B. 检索质量**
- `search_memory()` 返回类型：`str | None` → `[(doc_json, similarity_score, metadata), ...]`
- top-k 默认 3（Agent 可看到多个候选）
- 相似度阈值 0.4（低质量匹配自动过滤）
- 命中时自动更新 `last_accessed` 和 `access_count`

**C. 生命周期管理**
- 每条记录含 `created_at` / `last_accessed` / `access_count`
- LRU 淘汰：上限 500 条，超出时删除最久未访问的条目
- 新增 `list_entries()` / `delete_entry(id)` / `get_stats()`

### 文件改动

|------|------|
| `tools/chem_memory.py` | 重写（~120 行新增） |
| `app.py` | 新增知识库浏览器 UI |
| `tests/conftest.py` | FakeCollection 添加 `update` + 真实余弦相似度 |

## PubChemTool——SMILES → 名称解析

### 问题

ChemSpider 只支持名称检索。用户通过 Ketcher 画出结构得到 SMILES，但 Agent 无法识别这是什么化合物。

### 解决

新增 `tools/pubchem_search.py`，调用 NIH PubChem REST API（免费，无需 Key）：

```
SMILES → https://pubchem.ncbi.nlm.nih.gov/rest/pug/compound/smiles/{SMILES}/property/.../JSON
      → {Title, IUPACName, MolecularFormula, Synonyms, ...}
```

- `PubChemTool._run(smiles)` → 解析化合物名称、IUPAC、同义词
- 结果自动存入知识库
- `search_pubchem_synonyms(smiles)` → 获取中英文同义词列表

### 测试

`tests/test_pubchem_search.py` 新增 9 项（mock HTTP）

## Tool Registry——统一工具注册中心

### 问题

每次新增工具需要修改 `multiagent.py` 的 import 和 `chem_tools` 列表两处，容易遗漏。

### 解决

创建 `tools/__init__.py` 作为注册中心：

```python
CHEM_TOOLS = [ChemicalMemoryTool(), ChemSpiderTool(), PubChemTool(),
              ChemCalcTool(), StructureAnnotationTool()]
LITERATURE_TOOLS = [CrossrefSearchTool()]
```

`multiagent.py` 简化为一行：
```python
from tools import CHEM_TOOLS, LITERATURE_TOOLS
chem_tools = CHEM_TOOLS
literature_tools = LITERATURE_TOOLS
```

新增工具只需在 `tools/__init__.py` 加一行 import + 一行实例化。MCP 暂不引入（对本地工具过重）。

## 技术调研（暂未实施）

### MSDS / 化学品安全数据

调研结论：没有统一的 MSDS API。PubChem 提供 GHS 分类 + LCSS 实验室安全摘要（免费 REST API），可覆盖 GHS 信号词、象形图、H/P 编码、LD50 等核心安全信息。完整 16 节 SDS 数据分散在各供应商网站，无统一接入方式。

### 单 Agent 模式评估

`agents/agent.py` 是一个简单 ReAct 循环，缺 PubChem / StructureAnnotator / 文献检索 / 流式输出，已严重落后于多 Agent 模式。建议移除，前端默认已切换为多 Agent 模式。

## 修复：上下文污染 + 流式糊脸 + 2D 图不主动

### 问题来源

从导出的对话记录中发现三个严重影响体验的 bug：

1. **Agent 忘记检索过的内容**：查询 6 个 AIE 荧光分子后，Agent 丢失了前面检索的信息。根因是 ChemSpider 返回的 `mol2D`/`mol3D` 字段包含数百行 Molfile 坐标数据（每个化合物 ~5000 字符），6 个分子就占用了 ~30KB 上下文，把真正有用的化学信息挤出了 LLM 注意力窗口。

2. **流式输出满屏 V2000**：坐标数据被逐字符渲染到前端，用户看到的是 `5.9845 -8.0687 0.0000 C 0 0 0...` 这样的垃圾信息。

3. **2D 结构图不主动生成**：Agent 拿到 SMILES 后不调用 ChemCalc，需要用户明确要求才会生成图片。

### 修复：三层数据过滤

| 层 | 位置 | 改动 |
|----|------|------|
| 存储层 | `chemspider_search.py` | 完整数据（含 mol2D/mol3D）存入知识库，保留 3D 渲染潜力 |
| LLM 层 | `chemspider_search.py:_run()` | 返回 Agent 的 JSON 剥掉 mol2D/mol3D，只传有意义的化学信息 |
| UI 层 | `app.py:_strip_molfile()` | 正则匹配 V2000/V3000 坐标块，替换为 `[2D/3D 结构坐标数据已存入知识库]` |

### 修复：提示词强化

- **化学专家节点**：重写系统提示，明确 "拿到 SMILES 就立刻调用 ChemCalc，不要等用户要求" + 4 步工作流程
- **汇总节点**：5 条格式化规则，第 1 条就是有 SMILES 必须生成 2D 结构图

### 新增函数

`app.py: _strip_molfile(text: str) -> str` —— 移除 Molfile V2000/V3000 坐标块和 PubChem 注释块的正则过滤器
